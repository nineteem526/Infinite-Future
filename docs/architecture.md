# 技术架构与决策

2026-11-08：空目录无现成工程，采用 TypeScript、Vite、Three.js、Rapier。两时代预加载，共享坐标；渲染与物理数据独立，逐时代启停。固定时间步推进物理；切换前检测玩家胶囊体目标位置；安全时保持原坐标，不安全时在 1 米内按固定顺序寻找安全点，检查来源时代的移动路径，站立时要求目标时代有支撑，空中切换保留速度；找不到安全点才保持原状态并提示。切换事务同帧更新物理、视觉、环境光与音频状态；没有网络请求或加载。

模块边界：TimeShift.request(target) 返回成功或拒绝原因，通过接口读取玩家姿态/碰撞查询并提交时代；Player 管理输入、控制与速度；Era 管理已加载渲染/碰撞/光音；WorldState 管理确定性标志、唯一物品和因果；交互、事件和剧情只经 WorldState 通信。实现可按 M1 实际需要调整，但接口变更须记录。

Git：main 只接收运行及验收通过的集成；各任务使用 task/<id> 分支或隔离工作树，事先声明文件所有权，完成后审查差异、构建和实际运行后集成。任务不得并发编辑同一文件；资产保留原始文件、生成资源另行追踪，勿随意提交大型二进制。单人启动阶段未形成基线前先在 main 建立可运行基线；尚未通过验收的工作明确标示。

M1 实际实现：两时代的碰撞体常驻同一个 Rapier 世界；角色控制和目标胶囊检测均按时代谓词过滤。这样查询不依赖碰撞体启停后 broad-phase 的刷新时序。切换时同步改变 WorldState、可见组、环境、HUD 和音频。

关键机关通过 Physics.registerDynamicCollider 注册时代、激活状态和受保护标记。受保护物体占据目标位置或安全落点调整路径时禁止自动挪动越过它；开启后才从移动及切换安全查询中排除。M2 未来闸门已按此接口注册；状态由 WorldState 驱动，关闭时属于受保护碰撞体。

M2-001：晶体唯一状态使用 world/inventory/socket 互斥表示；F 交互经 CausalitySystem 分发到 WorldState 确定性规则。发电机供能后才可操作过去装置，之后未来闸门开启，R 重置。显示和碰撞由同一状态驱动。

## M4 建筑装饰接口 · 2026-11-08
新增 dressWorld(eras)，仅在 Game 创建主线内容后调用一次。它拥有独立 architectural-finish 子组，不修改结构网格、状态或碰撞体；实例化装饰与额外画廊灯随所属时代组同步切换，三个原画保持独立。新增装饰采用固定位置与序号计算，无随机或在线生成。

M4-002：dressExterior 作为 dressWorld 的内部视觉模块调用；结构石材克隆材质，着色器根据世界坐标提供接缝与颗粒，不改几何和碰撞。天空、环境补光归所属时代组；背景城市与树木严格位于可行走边界外。主要重复建筑沿用实例化批次，无运行时生成任务。
